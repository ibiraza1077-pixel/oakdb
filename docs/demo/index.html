Crash test

Commit five transactions of ten rows, then kill the process: no close, no checkpoint. Optionally cut the write-ahead log halfway through the last commit, as a power cut would. Reopening runs WAL recovery.

    Engine

    Transaction: idle

    Files

    oak.db0 B
    oak.db-wal0 B
    WAL until checkpoint0%

    Each 4 KB page write goes to the WAL as a 4,120-byte frame with a chained CRC-64 checksum. A torn frame breaks the chain, so recovery keeps exactly the committed prefix. In the browser, fsync has nothing to flush, so the crash test cuts the WAL file directly, the same way the repository's torn-write tests do.
