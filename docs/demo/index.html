Rev. — Crash test

kill −9, in a browser

Commit five transactions of ten rows, then kill the process: no close, no checkpoint. With the tear on, the WAL is cut part-way through the last commit, as a power cut would leave it. Reopening runs recovery; watch it walk the tape below.

    Fig. 1 — oak.db-wal

    0 frames
    written by your last commandcommit frameverified by recoverydiscarded

    Every committed page is appended as a 4,120-byte frame: page number, commit flag, salt and a CRC-64 chained to the frame before it. At 1,000 frames a checkpoint folds them into oak.db and the tape starts again.

    The page map reads each page's first byte, which OakDB's B+tree uses as the node type; newer copies in the WAL override the file. In a browser fsync has nothing to flush, so the crash test cuts the WAL directly, the same way the repository's torn-write tests do.
